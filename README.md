# 时尚百货城自动化

当前发布版本：**1.1.1**（2026-08-27）。版本变化见 [`CHANGELOG.md`](./CHANGELOG.md)。

基于 [MaaFramework](https://github.com/MaaXYZ/MaaFramework) 的 Windows 桌面自动化项目，通过 MuMu 模拟器的 ADB 接口完成《时尚百货城》的登录、弹窗处理和部分日常任务。

项目提供 Tkinter 桌面客户端，也支持直接从命令行运行。自动化流程以 OCR、颜色识别、固定坐标和跳转确认共同驱动；页面状态不明确时会停止操作，避免继续点击或消费资源。

> [!IMPORTANT]
> 当前流程按 MaaFramework 的 **720×1280 竖屏识别坐标**配置，并针对 **MuMu 模拟器 12** 的截图通道编排。客户端会在打开游戏并到达登录页后检查分辨率，把 1080×1920、1440×2560、2160×3840 等 9:16 竖屏分辨率自动缩放到该坐标系；其他宽高比会在此时停止。打开游戏前的模拟器桌面分辨率不参与校验。

## 功能

- 登录账号、勾选协议并按目标区号选服。
- 首页支持通过“＋ 添加账号”维护有序账号队列；可拖动每行左侧“↕ 序号”调整执行顺序，每个账号也可单独勾选“使用”或暂时停用。开始运行后顺序锁定。
- 多账号按列表顺序执行；当前账号只有在领取 100 活跃礼包并安全关闭游戏后，才会重新打开游戏执行下一个账号。
- 首次进入日常页时从顶部滚动到底部盘点受支持任务，按同行位置区分“前往”“领取”和“已领取”；只执行仍显示“前往”的任务，已完成或已领取任务直接跳过。
- 处理离线收益、每月签到、幸运赠礼及重复出现的登录赠礼。
- 自动关闭可能在任意阶段打断流程的活动弹窗。
- 严格确认日常页和任务目标页；点击未跳转时有限重试。
- 登录完成后直接从底部“百货”进入，蛇形收集最先出现的 3 家绿色店铺，选择其中等级最低者执行升级，不经过日常“前往”。
- 在消费动作前确认“连升十级”“一键进货”“一键宣传”等绿色勾选状态。
- 逐项领取日常奖励；仅在确认活跃度达到 100 后领取最终礼包。
- 记录持久化会话日志，并为每个关键步骤生成调试截图。
- 首页可独立开启报错诊断包：任一运行模式发生异常时，将最近 5 步操作与对应截图压缩为“账号名_时间.zip”。
- 首页可开启“进程错误恢复”模式：单个账号执行异常时不弹窗，关闭游戏后继续下一个账号。
- 正常关闭客户端时删除本次日志和调试截图；异常退出时保留现场用于排查。

## 环境要求

- Windows。
- 使用便携版时无需安装 Python；从源码运行或打包需要 Python 3.13。
- MuMu 模拟器 12，并启用可用的 ADB 连接。
- 游戏打开后使用 9:16 竖屏分辨率，例如 720×1280、1080×1920、1440×2560 或 2160×3840；打开游戏前的模拟器桌面分辨率不限。
- 中文 OCR 模型文件：
  - `resource/model/ocr/det.onnx`
  - `resource/model/ocr/rec.onnx`
  - `resource/model/ocr/keys.txt`
- 输入账号和密码前，将 Windows 输入法切换为英文；当前安全输入仅支持可打印 ASCII 字符。

## 快速开始

### 便携版（推荐）

解压 `FashionMallAutomation-v1.1.1-Windows-x64.zip`，启动 MuMu 模拟器后双击 `FashionMallClient.exe`。便携版已经包含 Python、MaaFramework、OCR 模型及所需原生库，不需要安装 Python 包。可使用同目录的 `FashionMallAutomation-v1.1.1-Windows-x64.sha256` 校验下载文件。

客户端桌面界面支持 1920×1080、2560×1440 和 3840×2160，并会结合 Windows DPI 自动调整窗口、字体和间距。

请将压缩包完整解压到仅自己可访问的可写目录，不要直接在压缩包内运行。当前程序未进行商业代码签名；如果 Windows SmartScreen 提示未知发布者，请先核对压缩包来源及 SHA-256。MuMu 模拟器 12 和游戏仍需用户自行安装。

### 从源码运行

在项目根目录创建虚拟环境并安装依赖：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

> [!NOTE]
> `requirements.txt` 声明 MaaFw 5.12 至 6.0 之前的版本，并包含用于保存逐步调试截图的 Pillow。

### 构建 Windows 便携版

项目根目录只保留一个可双击发布入口：`发布便携版.bat`。该批处理文件使用 Windows 兼容的 ASCII/CRLF 格式，并调用内部的 `tools/build_portable.ps1` 执行完整发布流程。需要在终端中运行时执行：

```powershell
.\tools\build_portable.ps1
```

脚本按以下规则执行：

- 自动完成版本与文档一致性检查、Python 编译检查、全部单元测试、依赖准备、PyInstaller 构建、便携版自检、压缩、敏感文件审计和 SHA-256 复核。
- 任一步失败都会停止，不会把失败结果当作可发布版本，并保留 `build/`、`dist/` 和 Python 缓存用于排查。
- 全部门禁通过后，自动删除 `build/`、`dist/` 以及根目录、`fashion_mall/`、`tests/` 下本次产生的 `__pycache__/`。
- 每个清理目标都会解析为绝对路径并校验其位于项目根目录内，拒绝删除项目目录之外的路径。
- `.venv/`、`runtime/` 和历史发布包不会被自动清理；最终发布结果保存在 `release/`，包括带版本号的 ZIP 和 SHA-256 校验文件。

需要排查打包结果时，可在终端中保留中间文件：

```powershell
.\tools\build_portable.ps1 -KeepBuildArtifacts
```

### 运行测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
```

测试仅保留在维护者本机，不由 Git 跟踪，也不会复制进便携版或远程源码仓库。

确认 OCR 模型文件已经放入 `resource/model/ocr/`，启动 MuMu 模拟器并保持在桌面或游戏登录页，然后双击：

```text
启动客户端.bat
```

在客户端填写游戏账号、密码和目标区号；需要多账号时点击“＋ 添加账号”，通过每行左侧“↕ 序号”拖拽排序，并通过右侧“使用”勾选决定本轮是否执行。需要留存错误现场时开启“发生错误时将最近 5 步操作和截图打包为 ZIP”（默认开启）；需要无人值守跳过异常账号时，另行开启“进程错误时关闭游戏并继续下一个账号”。点击“开始运行”后，账号顺序和运行模式会锁定并按当前列表推进。任务执行期间可以点击“停止”；程序会在当前识别动作结束后安全退出。

## 命令行运行

也可以在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe .\runner.py
```

首次运行会提示输入账号、密码和区号，之后会读取本地账号队列配置。命令行也只执行其中已勾选“使用”的账号。

## 配置与数据

客户端会按当前项目约定，将账号队列、密码、目标区号、启用状态、进程错误恢复模式和报错诊断包开关保存到：

```text
runtime/config/client_config.json
```

可通过客户端的“清除本地配置”按钮删除该文件。凭据通过 ADB Shell 的标准输入发送，不会作为命令行参数写入；会话日志也不会主动记录账号或密码。

可选环境变量：

| 变量 | 用途 |
| --- | --- |
| `ADB_PATH` | 指定兼容回退使用的 `adb.exe` 绝对路径 |
| `FASHION_MALL_PACKAGE` | 限制流程结束时允许停止的前台游戏包名 |

未设置 `FASHION_MALL_PACKAGE` 时，运行器仍会先读取并检查当前前台包名；无法安全确认时会保留游戏运行，也不会关闭模拟器。

## 识别与安全策略

- 日常任务通过任务标题定位同一行的“前往”，并要求明确识别目标页面。
- 点击后仍停留在原页面时会有限重试；目标页和原页都无法确认时停止。
- 店铺升级使用有限蛇形扫描，按店名去重并在取得 3 个有效候选后立即停止；生鲜进货仍使用日常任务定位的生鲜超市。
- 进货界面和生鲜超市均使用左下角返回按钮固定坐标 `(50,1230)`，点击后继续验证目标页。
- 绿色勾选无法确认时不会执行升级、进货或宣传等消费动作。
- 奖励层使用左上安全空白区域关闭，避开“再次进货”“去上架”“抽十次”等按钮。
- 活跃度不足 100、奖励页状态不明确或前台包名无法确认时，不会退出游戏。
- 默认模式下，只要当前账号未确认完全完成或游戏未能安全关闭，就会停止整个账号队列。开启进程错误恢复模式后，仅“执行抛出异常且游戏已确认关闭”的账号会被跳过；活跃度不足等未完全完成状态仍会停止队列。报错诊断包开关与是否继续下一账号相互独立。

> [!WARNING]
> 本项目会在本机保存明文登录凭据。请只在可信设备上运行，并确保自动化用途符合游戏服务条款。

## 日志与调试截图

桌面客户端启动后会在 `runtime/debug/` 创建临时会话现场：

- `session-*.log`：流程节点、扫描次数、跳转确认和错误信息。
- `screenshots-*/step-*.png`：Maa 任务、固定点击、滑动和 ADB 输入后的顺序截图。

开启报错诊断包并实际遇到异常时，无论当前选择“立即中断”还是“关闭游戏并继续下一账号”，都会在 `runtime/error-diagnostics/` 生成 `账号名_时间.zip`。ZIP 内包含最近 5 步操作对应的 PNG 截图及 `recent-steps.log`；日志记录账号、错误信息和对应操作，但不记录密码。文件名中的 Windows 非法字符会替换为下划线。诊断 ZIP 在正常退出客户端时也不会删除，用户可直接发送给维护者分析。

日志中的截图编号与 PNG 文件一一对应。正常关闭客户端时，会等待工作线程结束，然后删除本次会话日志以及全部 `screenshots-*` 调试目录；客户端崩溃或被强制结束时会保留这些文件，便于查看最后停留页面。

## 常见问题

### 没有发现 MuMu 模拟器

确认 MuMu 模拟器 12 已启动并启用 ADB。当前安装路径无法自动识别时，可设置 `ADB_PATH` 后重试。

### 提示缺少 OCR 模型

检查 `resource/model/ocr/` 下是否同时存在 `det.onnx`、`rec.onnx` 和 `keys.txt`。

### 页面已经打开，但识别仍失败

不要立即修改整个流程。先查看最新的 `runtime/debug/session-*.log`，再按日志中的 `step-*.png` 编号检查实际画面。常见原因包括弹窗遮挡、模拟器不是 9:16 竖屏、页面尚未加载完成或 OCR ROI 需要重新校准。

### 正常关闭后找不到调试截图

这是预期行为。正常关闭客户端会主动删除调试截图；需要排查时，请在关闭客户端前查看或复制截图。异常退出产生的截图会保留。
