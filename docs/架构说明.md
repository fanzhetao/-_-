# 项目架构说明

项目保留根目录的 `client.py`、`runner.py` 作为 Windows 双击入口、命令行入口和
历史调用的兼容层。可复用且与界面/设备无关的逻辑逐步放在 `fashion_mall/` 包内，
避免把 PyInstaller 入口和业务实现绑定在一起。

## 代码分层

```text
client.py
└─ Tkinter 窗口、账号队列、线程生命周期和会话日志
   ├─ fashion_mall.ui_helpers
   │  └─ 无界面的列表排序与 DPI 缩放计算
   └─ fashion_mall.diagnostics
      └─ 任一错误处理模式下最近五步操作与截图的独立 ZIP 归档

runner.py
├─ 兼容入口、MaaFramework/ADB 设备生命周期
├─ 页面导航、弹窗恢复和日常业务流程
├─ fashion_mall.devices
│  └─ MuMuManager、ADB 设备发现（不连接设备）
├─ fashion_mall.daily_rules
│  └─ OCR 文本归一化、日常任务分类和同行按钮几何计算
├─ fashion_mall.store_scan
│  └─ 百货绿色店铺识别、名称等级配对、候选去重与最低等级选择
├─ fashion_mall.client_state
│  └─ 账号队列筛选、进度和失败消息
├─ fashion_mall.maa_ops
│  └─ Maa 作业等待、成功判断和临时节点覆盖
├─ fashion_mall.retry
│  └─ 可注入的有限重试/恢复控制流
├─ fashion_mall.self_check
│  └─ 不初始化 GUI/设备的便携版内容自检
└─ fashion_mall.config
   └─ 配置 JSON 读取、旧格式迁移、校验回调和原子写入

入口启动时由 `fashion_mall.paths` 统一解析源码运行、PyInstaller bundle 和
用户运行目录；它只计算路径，不创建目录，也不读取本机配置。
```

`fashion_mall.config` 不导入 Tkinter、MaaFramework 或设备对象，因此可以快速做
单元测试。账号校验仍由 `runner` 提供并通过回调注入，现有外部调用和测试对
`runner.CLIENT_CONFIG_PATH`、`runner.validate_*` 的替换行为保持不变。

## 文件分类约定

- 根目录：用户可直接双击的启动/发布入口、版本文件和少量依赖清单。
- `tools/`：开发维护脚本；发布实现位于 `tools/build_portable.ps1`，不作为第二个根目录入口。
- `fashion_mall/`：按职责拆分的 Python 实现；新增纯逻辑优先放这里。
- `resource/`：MaaFramework 流程和 OCR 模型，只读随发布包收集。
- `README.md`：唯一的使用、配置和开发入口，随发布包分发。
- `CHANGELOG.md`：仅记录版本历史，随发布包分发。
- `docs/`：只保存内部架构与维护说明，不重复用户使用文档。
- `tests/`：本机验证用测试，不进入源码仓库或便携版。
- `runtime/`：本机配置、日志和截图，禁止复制到发布包。
- `build/`、`dist/`、`release/`、`.build-deps/`：可重新生成的构建产物，不手工维护。

## 演进规则

1. 先把无外部副作用的转换、校验和数据结构移到 `fashion_mall/`，再处理设备流程。
2. 根入口只保留兼容导出和生命周期编排，不改变 `启动客户端.bat`、spec 或发布脚本
   的入口路径。
3. 每次拆分后运行完整 unittest；真实 MuMu 画面验证仍单独记录，不能由单元测试替代。
4. 任何配置、日志和截图相关改动都必须继续遵守 `runtime/` 敏感数据边界。

纯规则模块通过参数传入状态名称、任务规格和匹配函数，不反向导入 `runner`，
因此可以在无模拟器环境中直接测试；`runner` 仅负责兼容导出和运行时依赖适配。

客户端的 Tkinter 类只负责控件生命周期、线程启动和事件派发；账号筛选、队列
进度文案和有限重试骨架位于无界面模块中。取消异常由调用方注入并原样传播，
不会被重试工具吞掉。

业务任务错误继续模式由 `runner.run_automation` 在登录成功后的业务任务边界捕获
异常，通过客户端回调强制归档最近五步 ZIP，再安全关闭游戏、重新登录当前账号并
恢复到主页或日常页。设备连接、初次登录、重新登录和安全关停属于基础生命周期，
不在可跳过范围内；任一恢复失败仍会停止流程。

便携版自检先写入内部阶段标记，再校验 `VERSION`、OCR 模型和 Maa 运行库；只有
全部通过后才写入 `ok`。这使发布脚本可以区分启动失败与检查失败。
